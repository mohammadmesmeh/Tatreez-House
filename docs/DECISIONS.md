# Decisions log

Short, dated record of project decisions and why they were made. Newest milestone first.

## 2026-10-24 — One link underline: the shared stitch utility, branch `fix/stitch-underline`

| # | Decision | Reason |
|---|---|---|
| 1 | **`.th-stitch` is the theme's only link underline** (in `assets/tatreez-tokens.css`). It goes on the inline element that wraps the words; it is drawn on hover and keyboard focus of the element or its link, on the current page (`aria-current`, `.header__active-menu-item`, the drawer's active section), on an open dropdown trigger, and always with `--persistent` (drawn heavier on hover/focus). It replaces the four separate stitch rules (header items, dropdown labels, card titles, `.th-link`). | The nav showed Dawn's solid underline stacked on the stitch (QA, "Workshops" current item): Dawn underlines `.header__menu-item:hover span`, `details[open] > .header__menu-item` and the active item, and a nested span had given those rules a new target. |
| 2 | The utility removes `text-decoration` from the stitch, its descendants and the link/summary/button around it, with `!important`; the `:has()` part is a separate rule. | Text decorations propagate to the text, so every level must be cleared; Dawn's state selectors are more specific; a browser without `:has()` then only loses that one rule. |
| 3 | Content links (rich text), the language selector and Dawn's "View all" link keep Dawn's single solid underline; footer, menu, card, Details and teaser links use the stitch. | One underline style per state everywhere; content links stay underlined at rest (WCAG 1.4.1). |
| 4 | Guarded by `scripts/tests/underline_audit.py` (every audited element, EN + /ar) and the dropdown suite (stitch drawn and no text-decoration anywhere along it for current, hover, focus and open; neither at rest). | A future link cannot double up unnoticed. |

## 2026-10-22 — Header: compact dropdowns instead of mega menu panels, branch `header-dropdowns`

| # | Decision | Reason |
|---|---|---|
| 1 | Desktop menus use Dawn's **dropdown** type (header setting "Desktop menu type" = Dropdown) restyled as a compact card: anchored under its own trigger at the inline-start (mirrors in RTL), content width (min 220px), 8px below the header edge, ivory surface, 1px linen border, soft shadow, 2px radius, 44px Nunito rows with the stitched underline. Replaces M2 #9's mega menu panels. | Two short menus (Shop 4 links, Learn 3) don't need full-width panels; a small card keeps the eye near the trigger. Using the existing setting keeps it merchant-reversible. |
| 2 | **The mega menu featured-card settings stay in the header schema, unused** while the menu type is Dropdown (they only render with the Mega type; the editor info already says "Requires the mega menu type on desktop"). Values in `header-group.json` are kept. | Preserves merchant configuration and setting IDs (AGENTS.md); switching back to Mega restores the card with no data loss. Deleting them would silently drop the owner's Clothing card setup. |
| 3 | Behaviour lives in Dawn's `HeaderMenu` (details-disclosure.js): hover opens on real pointers (150ms grace on leave), a click on a hover-opened trigger keeps it open, outside click and focus leaving close, one menu at a time, `aria-expanded` synced on every toggle. Escape (global.js) closes and returns focus. | One implementation for click, keyboard and hover; `<details>`/`<summary>` keeps it working without the enhancement. |
| 4 | The card's top offset is measured on open (`--th-dropdown-offset`), so it sits 8px under the header edge whatever the header padding or sticky state. | The trigger is vertically centred in the header, so a fixed `top` would land inside the header at some paddings. |

## 2026-10-22 — Milestone M4 (events: workshops and community circles), branch `m4-events`

| # | Decision | Reason |
|---|---|---|
| 1 | **Events are ordinary products, not a booking app.** Each workshop or circle is a product, each date is a variant (option `Date`, `YYYY-MM-DD HH:MM`, Palestine time), seats are inventory, `requires_shipping` is off, free circles are $0 products. | No monthly app subscription for the client; booking runs through Shopify's own cart and checkout (payments, taxes, order emails, refunds); "seats left" is real inventory; a non-technical owner adds a date in under a minute. See `docs/store-setup/EVENTS-SETUP.md`. |
| 2 | Limits accepted with #1: no automatic Zoom links, reminders, waitlists or attendee lists beyond orders. The owner sends the Zoom link by email (docs/OWNER_GUIDE.md); see who booked under Orders filtered by product. | Fine for a small studio. If volume grows, add a free app later (e.g. order-tagging or email automations via Shopify Flow / Shopify Email) without changing the theme. |
| 3 | **Time zone rule** (`snippets/event-date.liquid`): Palestine summer time (+03:00) from the last Saturday of March to the day before the last Saturday of October, otherwise +02:00. Dates are parsed with that explicit offset, so "upcoming" and the `<time datetime>` are correct whatever the shop's time zone setting is. | Liquid has no time zone database. Palestine sometimes moves the change (e.g. around Ramadan); in those weeks the offset can be one hour off, so the owner should avoid scheduling in change weeks or double-check the `.ics`. The Google Calendar link uses `ctz=Asia/Hebron` and is always right. |
| 4 | Dates are formatted from the option value's parts, not with `| date`, with weekday/month names and patterns in the locales (EN "Sat, 7 Nov 2026 · 6:00 PM", AR "السبت، 7 نوفمبر 2026 · 6:00 م"), always followed by "Palestine time" / "بتوقيت فلسطين". Latin digits in both languages. | `| date` formats in the shop's time zone and English month names; the value is already Palestine wall time. |
| 5 | Past dates are never offered (listing, chips, cards, teaser); sold-out upcoming dates show "Fully booked" and are disabled. A malformed date value renders as raw text and is logged in the theme editor only. | Honest availability; the page never breaks on owner typos. |
| 6 | Events page filters are links (`?type=workshop`) with `aria-current`, applied by a small script; without JS every session shows. | Shareable filtered views; Liquid cannot read query strings, so filtering is client-side. Links + `aria-current` is the correct pattern for navigation-like filters. |
| 7 | Session lookups use sort keys `timestamp:product_index:variant_index` from `snippets/event-session-keys.liquid`. | Liquid cannot sort objects; index keys avoid nested scans over every product and variant (code review finding). |
| 8 | Free circles: no dynamic checkout ("Buy it now") button, "Reserve my free spot" adds to cart, the cart checkout completes with no payment. | Express wallets are not meant for $0 orders; Shopify checkout shows "Your order is free. No payment is required." |
| 9 | The booking label and the session info are restored/swapped after each date change by `event-session.js`, loaded by the buy buttons (not by an optional block). | Dawn's product-form resets the label to "Add to cart" on every variant change; tying the fix to an optional block would break when the block is removed (code review finding). |
| 10 | The newsletter form is one snippet (`newsletter-form`) used by the footer and the events empty states. | No duplicated form markup. Shopify's posted state is not scoped per form, so two forms on one page both show the result (documented limitation). |
| 11 | Featured collection skips the product being viewed (used for "Other upcoming sessions"). | A product never recommends itself; no effect on pages without a product. |
| 12 | The events suite runs on the real store domain through a theme preview (`--preview-theme`). | The `shopify theme dev` proxy cannot reach checkout, and a password login on the real domain invalidates the proxy's storefront session. |

## 2026-10-21 — Milestone M2.1 (wiring and verification), branch `m2-wiring`

| # | Decision | Reason |
|---|---|---|
| 1 | Scroll-reveal content is **visible by default**; the slide-in animation only runs when JS has marked the element (`th-reveal-run`) and `html.js-reveal-ready` is set. | Root cause of the hidden content: Dawn sets `.scroll-trigger` to opacity 0.01 and depends on JS to reveal it; late or failing JS, previews and Lighthouse left content invisible. |
| 2 | Hero slideshow timing is a CSS animation (`animationend` advances the slide; `animation-play-state` pauses it). Header turns transparent only when the slideshow is the first section in `<main>`. | One timer drives autoplay and the progress bar; pause/hover/focus/hidden/offscreen and reduced motion are all CSS states. Other pages keep the solid header. |
| 3 | Hero overlay floor 30% plus a 60% content scrim. | Ivory text needs ≥ 67% ink over a white photo for 4.5:1; floor + scrim give ≥ 72% whatever the merchant sets. |
| 4 | Card actions are always visible: "Add to cart" (one variant), "Choose options" (Dawn's quick-add modal), disabled "Sold out". Variant chips and inline forms removed from cards. | One button, one baseline per row on every grid; variant choice belongs in the modal or product page. |
| 5 | Ratings come only from Shopify's standard `reviews.rating` / `reviews.rating_count` metafields; nothing renders on cards without data, the product page shows "No reviews yet". | Never fake reviews; any reviews app that writes the standard metafields works (Judge.me does). |
| 6 | Compact cards via a container query, limited to phone-width screens (card ≤ 320 px, screen < 750 px). | Narrow desktop/tablet cards (e.g. 3 columns at 768 px) must keep full labels. |
| 7 | Homepage product rows on phones are a CSS scroll-snap list (82% items, ~1.28 cards visible), focusable for arrow keys, no JS. | Swipeable with the next card peeking; native RTL scrolling. |
| 8 | Swatch dots: Shopify swatch data first, then the "Swatch colours" theme setting (brand palette); unmapped colours show a neutral ringed dot; the hidden text names every colour. | Merchant-editable mapping; an unmapped colour is still understandable and announced. |
| 9 | **Minimal footer, no menu columns** (owner decision, 2026-10-21): brand + newsletter, language selector, policy links, copyright, demo-brand note. Replaces M2 #20 (footer accordions removed with `footer-accordion.js`). Payment icons, Follow on Shop and the country selector are off (settings kept). | Calmer footer; policies come from Settings → Policies, so no footer menus are needed. |
| 10 | Blank text settings fall back to translated defaults in the new footer fields and the mega menu card (empty heading → the linked collection's translated title). Extends M2 #16. | `/ar` shows Arabic without hard-coded English setting values. |
| 11 | New development store `tatreez-house.myshopify.com` (the previous store froze with HTTP 402). Theme code has no store-specific values; store data is recreated from `docs/store-setup/`. | Portability; the store can be rebuilt. |
| 12 | Acceptance suites live in `scripts/tests/` and pick products by live availability (SKIP when no product is in the needed state). | Inventory changed during testing (all physical products briefly sold out). |
| 13 | The `[shopify-account] Menu … not found in Storefront API` console message is left as is. | The menu exists for Liquid; the account component's API lookup does not find it and falls back to the same default items. Not fixable in theme code. |
| 14 | **Permanent theme: "Tatreez House", ID `189100294237`** on `tatreez-house.myshopify.com` (live, published by the owner from the admin; Horizon is unpublished). 2026-10-22: editor state pulled first (logo, favicon, hero and path card images merged into the repo), then `m2-wiring` pushed with `--allow-live` at the owner's request; a pull-back showed the theme identical to the repo. | One long-lived theme that both the editor and the repo update; pull before every push (README) so editor changes are never overwritten. |

## 2026-10-20 — Milestone M0 (foundation), branch `002-foundation`

| # | Decision | Reason |
|---|---|---|
| 1 | Withdraw the Thmanyah Arabic fonts (Thmanyah Sans, Thmanyah Serif Display): WOFF2 copies deleted, `@font-face` rules and stack references removed, source archive moved **out of the repository** (to `C:\Tatreez House-private-fonts\`, not deleted). | Its licence forbids web embedding and hosting the files for download, so it cannot be served from Shopify's CDN or kept in a public repo. | 2 | Arabic body/UI = **Zain** 400/700; Arabic headings = **Amiri** 400/700; both from google/fonts, subset to Arabic, `unicode-range`-scoped. No Zain 300. | SIL OFL 1.1 permits self-hosting. | 3 | **Nunito** for Latin body, UI *and* headings (700). **Playwrite NZ Basic** moves out of the heading stack into an opt-in `.font-accent` class. | A handwriting script as the default heading face hurts readability and accessibility. |
| 4 | One shared `snippets/theme-fonts.liquid` (preload, `fonts.css`, `--font-*` variables) rendered by the theme layout, the password layout and the gift card template. | Removes three copies of font logic; one place to change fonts. |
| 5 | Stop outputting the font pickers' `font_face`, preload and `fonts.shopifycdn.com` preconnect. Keep the `type_header_font` / `type_body_font` settings (IDs preserved) with an `info` note. | Assistant was declared and preloaded but never used. Keeping the settings avoids breaking saved editor data. |
| 6 | Arabic text gets `letter-spacing: 0`; Arabic headings get `line-height: 1.55` (1.45 for `h0`/`hxl`/`hxxl`). | Tracking breaks cursive joins; Amiri's tall metrics (1.758 em) made stacked marks collide at Dawn's ~1.3. Checked visually h0–h5. |
| 7 | Keep the admin colour schemes exactly as configured, including off-palette values (`#17352B`, `#F7F2E8`, `#252722`, `#8C2633`, `#F0E8D9`); report them instead. | The admin is the source of truth for settings; every pair passes WCAG AA (`scripts/contrast-check.mjs`), so there is no accessibility reason to override. |
| 8 | Hero colours come only from the colour scheme; the image overlay uses the scheme background instead of black. | No hex values in custom CSS; text and overlay always come from the same scheme, so contrast holds for any scheme the merchant picks. |
| 9 | Ship only `en.default.json`, `en.default.schema.json` and `ar.json`; delete 49 other locale files and `ar.schema.json`; re-enable `MatchingTranslations` (removing `.theme-check.yml`). | The store supports English and Arabic only. The merchant edits in English, so Arabic schema strings add upkeep without value. |
| 10 | Remove the 49 hero editor-label keys from the **storefront** locale; keep only the two copy defaults the section renders with `| t`. | Editor labels belong in the schema locale. This keeps `ar.json` identical in shape to `en.default.json` with no dead keys. |

| 12 | Hero alignment/position values renamed `left/right` → `start/end` (`top-left` → `top-start` …). | Values now describe reading direction and mirror in RTL. The placed hero uses `middle-center`/`center`, so no template migration was needed. |
